# W11-A — local Bridge APK backend contract (Issue #63)

**Experimental internal library only; NOT wired to JavaFX, Web, or the photo-transfer coordinator.** No Windows release or watch hardware acceptance is implied. `watch-adb` uses pinned offline Java libraries `apksig 8.13.2` (Android signing verification; Google Maven) and `ARSCLib 1.4.0` (Android binary manifest reading; Maven Central). Neither requires Android SDK, `aapt`, or `apksigner` on the end-user computer. Dependencies and bundled licenses require the ordinary distribution review before shipping.

## Caller responsibility and exclusive admission

1. Obtain explicit informed consent, the **exact selected watch serial**, and an already-authorized local bundled ADB executable. Do not accept browser-originated paths/requests. Acquire an **exclusive operation slot** atomically against active Desktop/Web photo transfers in W11-B before invoking this backend. The `BooleanSupplier` in `Request` is a recheck of that external slot, NOT its acquisition and NOT an atomic admission primitive. **No Desktop caller may invoke W11-A directly until W11-B exists.** Hold the slot until the installation call has exited, even when cancelled.
2. `new ApkPreflight().inspect(localPath, policy)` accepts exactly a local single `.apk`, rejects symlinks, split manifests, bundles, unsupported extensions, malformed/unsigned packages and unexpected package IDs; extracts version/minSdk and verifies cryptographic APK signatures. It returns file digest plus signing certificate SHA-256. Never return `Inspected.path` or unsanitized exceptions over HTTP or to diagnostic logs.
3. `new ApkInstallService().install(new Request(adbExecutable, serial, inspected, policy, leaseChecker))` creates a private temporary snapshot, checks the SHA-256, **re-verifies APK metadata and cryptographic signing on the exact staged bytes**, rechecks lease, uses `adb devices -l` and exact serial, queries `pm path` read-only, and runs `adb -s SERIAL install -r [-t only if manifest says testOnly] STAGED_APK`. It never uses shell interpolation, picks the first device, uninstalls, clears data, retries, or connects to an unauthorized device. It always attempts to clean up its staged copy.
4. `Result` exposes only a stable `Code` and safe English message; the caller owns future RU/EN localization. `INSTALLED` vs `UPDATED` is inferred from a read-only pre-install `pm path`. `SIGNATURE_MISMATCH`, `VERSION_DOWNGRADE`, `LOW_STORAGE`, `WATCH_OFFLINE`, `WATCH_UNAUTHORIZED`, `WATCH_MISSING`, `TIMED_OUT`, `INTERRUPTED` and other errors are distinct. A command timeout/interruption has **unknown device outcome**; operator must inspect the watch before choosing another explicit attempt, not automatically retry. An ADB `Success` proves only install command success, not Bridge launch, iPhone BLE function, or Galaxy Watch4 compatibility.

## Signing identity and rollout

- **DEBUG** (`Policy.explicitlyAllowDebug()`): explicit development-only opt-in, accepts any **cryptographically verified** signer certificate for the fixed Bridge package. It does **not** establish official publisher identity. CI-generated debug certificates can differ per run, so updating an existing package can fail; surface `SIGNATURE_MISMATCH` and never uninstall or clear data to force an update. Caller must display the package, signer SHA-256 and debug status for explicit human approval before installation (future W11-B UI responsibility).
- **OFFICIAL** (`new Policy(OFFICIAL, approvedSha256Set)`): requires a nonempty, explicitly approved **64-hex signing certificate fingerprint** allowlist. No release certificate is generated, invented, committed or inferred from CI/debug builds. `UNTRUSTED_SIGNER` fails closed. Before a production release, coordinator approves stable signing and identity/rotation policy. Package `io.github.aidarnig.wristporter.bridge` comes from in-flight W1-A PR #61; **revalidate package ID and APK signing contract after W1 merges**.
- The preflight exposes manifest minSdk but does not claim watch compatibility before real device checks. W11-B may compare it with a read-only SDK query. Different installed certificate is detected reliably by the **device package manager's install rejection**; W11-A does not scrape arbitrary `dumpsys` output to pretend it can cryptographically attest installed certificate identity.

Tests use a generated *synthetic* test-only signed fixture and fake ADB command runner, covering allowlist/signature, path, selection, timeouts, command arguments, refusal codes, lease revocation and immutable snapshot. No owner Watch4 test is appropriate for W11-A alone.
